# 시연 데이터 동선 (T156)

`npm run db:seed:dev -- --reset` 이 만드는 상태와, 각 스토리를 화면에서 따라가는 순서다. 확인 주소: https://p3.sumzip.com · 비밀번호: `backend/.env` 의 `SEED_DEMO_PASSWORD` (모든 시연 계정 공통).

시드는 DB 규칙(트리거)을 그대로 통과하도록 상태 전이 순서대로 넣고(요청 `received → analyzing → 결과`, 기록 `draft → saved`), 날짜는 실행일 기준 상대값이라 언제 다시 넣어도 지연·도래·만료가 재현된다. 실행 결과를 2026-10-03 에 화면·API 로 확인한 항목에 ✔ 를 붙였다.

## 공통 데이터

| 키 | 내용 |
|---|---|
| 한빛FM | 기업 고객사 · 라이선스 1년 남음 |
| 새솔관리 | 기업 고객사 · 라이선스 10일 전 만료 |
| 한빛오피스타워 A동 (건물 A) | 사무시설 · 건물관리시스템 `HB-A`(동기화 정상, 외부 이력 3건) |
| 한빛아파트 101동 (건물 B) | 공동주택 · 저장 기록 1건뿐 → 반복 하자 판단 불가(G7) |
| 한빛물류센터 (건물 C) | 사무시설 · 건물관리시스템 연동 실패(`FAIL-HB-C`) |
| 새솔빌딩 (건물 D) | 새솔관리 소속 — 한빛 사용자에게는 권한 밖 |

## US1 하자 사진 AI 분석

1. ✔ 시크릿 창에서 `/analysis` → 사진 + 설명 → [분석 요청] → 결과 카드(원인·대응방안) 안에 닫을 수 없는 '1차 참고용' 고지.
2. ✔ `general@dev.local` → 오른쪽 "내 분석 이력": 정상(균열)·주의(결로, 신뢰도 0.55 → 신뢰도 낮음 권고)·품질 부적합(G3)·분석 실패(G4) 4건. 상단 "무료 체험 1회 남음".
3. 설명에 `#danger` · `#caution` · `#lowconf` · `#fail` 을 넣으면 mock AI 가 그 결과를 낸다.

## US2 이용권 구매

1. ✔ `general.empty@dev.local` → `/analysis` 에 G2 블록 "분석 이용권이 없습니다 - 무료 체험을 모두 사용했습니다" + [이용권 구매].
2. `/purchase` → 요금제(건별 3,000원 · 월 29,000원)와 조건이 결제 버튼보다 위 → 카드 `4111-1111-1111-1111` 승인 → [분석 계속하기].
3. 카드 `4000-0000-0000-0002` → G1 "결제가 승인되지 않아…" + "카드 한도가 초과되었습니다". 결제 이력에 거절 1건이 미리 있다.
4. `general.expired@dev.local` → 월 구독이 어제 만료 → G2.
5. 비회원으로 분석 후 같은 창에서 로그인 → "이 기기의 분석 결과 연결" 제안.

## RBAC (인증·권한 관리)

1. ✔ `operator@dev.local` → 관리 > 권한 요청: facility.c@ 의 건물 A 요청, lead@ 의 건물 B 요청 대기. 승인하면 요청자가 다시 로그인하지 않아도 바로 진입.
2. `lead@dev.local` → 시설관리자 + 건물관리자 메뉴가 합쳐져 보인다.
3. `enterprise@dev.local` → 관리 > 계정·권한: 소속 조직(한빛FM) 사용자만 보이고, 새솔빌딩 권한 부여는 거부된다.
4. `disabled@dev.local` → 로그인 거부.
5. ✔ 권한 밖 화면 직접 접근(예: general@ 이 `/verification`) → 같은 주소에 G0 "이 화면을 볼 권한이 없습니다" + [권한 요청 보내기].

## US3 현장 점검·보수 기록

1. ✔ `facility@dev.local`(휴대폰 폭) → 현장 기록: 임시 저장 1건(1F 로비 바닥, 사진 없음), 추가 자료 요청 1건(주차 램프 벽).
2. [새 기록] → 건물 A → 연결 가능한 결과 "1F 로비 기둥 하부 균열" 선택 → 위치를 비우고 저장 → G5 + [누락 항목으로 이동] → 채워 저장.
3. AI 일치 여부 '불일치'로 저장하면 expert@ 의 검증 대기 목록에 즉시 나타난다.

## US4 전문가 검증

1. ✔ `expert@dev.local` → 전문가 검증: 대기 2건(지하 1층 기둥 · 3F 화장실 천장), 자료 요청 1건(주차 램프 벽).
2. '옥상 방수층' 건(검증 완료 필터) → 판정 이력 v1 일치 → v2 불일치.
3. 대기 건에서 [판정 불가] → 사유 입력 → [검증 완료] 가 G6 사유와 함께 비활성. facility@ 가 그 기록에 사진을 추가하면 대기로 돌아온다.
4. 2F 계단실 벽은 '위험 큼' 판정 → building@ 에게 위험 통지.

## US5 건물 이력·반복 하자

1. ✔ `building@dev.local` → 건물 이력 → 건물 A: 내부(분석·기록·판정·연결)와 외부 이력이 시간순으로 섞여 보인다.
2. 반복 하자 탭: 'B2 주차장 천장 · 누수'(내부 3 + 외부 2), '옥상 방수층 · 누수'. [정기점검 계획] / [전문가 연결] 로 대상이 미리 채워진 채 이동.
3. 건물 B → 반복 하자 탭 → G7 "이력이 부족해 반복 하자를 판단할 수 없습니다", 후속 버튼 비활성.
4. `enterprise@dev.local` → 건물 C → C7 "외부 이력 미반영"만 붙고 화면은 정상.

## US7 정기점검

1. ✔ `building@dev.local` → 정기점검 → 건물 A: 지연(기한 어제) · 도래(3일 후) · 예정(30일 후) · 완료 2 · 취소 1. 완료 중 'B2 주차장 천장 누수 긴급 점검'은 위험 표시 기록이 연결되어 전문가 연결 권고.
2. `cd backend && npm run job:p0` → 지연 일정 담당자(facility@)에게 지연 알림, 건물관리자에게 지연 표시 알림. 취소 일정에는 알림이 없다.
3. `facility@dev.local` → 내 배정 점검 → 지연 카드 [현장 기록 시작] → 저장하면 일정이 완료된다.

## US8 전문가 연결

1. ✔ `building@dev.local` → 전문가 연결: 열린 위험 통지(건물 A B2 누수 분석 · 계단실 위험 판정 · 정기점검 위험, 건물 B 2건)와 요청 4건(작성 중 · 수락 대기 · 미확정(expert.arch@ 거절) · 연결 확정).
2. B2 누수 통지 → [전문가 점검 요청] → 방수 · 이번 주 → 후보 expert@ → 수수료·공유 범위 고지 → 동의 없이 [요청 확정] → G9 → 동의 후 확정.
3. `expert@dev.local` → 점검 요청 → 동의된 범위의 자료만 보임 → [수락] → building@ 화면에서 연결 확정, 위험 통지 종료. 수수료 요율이 비어 있어 "요율 미설정 - 수수료 기록 없음".
4. 분야 '방수', 기간을 2주 뒤로 바꾸면 G8 "조건에 맞는 전문가가 없습니다" + [조건 바꾸기].

## US6 유지관리 우선순위

1. ✔ `enterprise@dev.local` → 유지관리 우선순위: 요약 4칸(누적 분석·조치 필요·다음 정기점검·전문가 일치율), 과거 산출 1건.
2. 과거 산출 열기 → '참고용' 고지가 목록 위에, "권한 밖 건물 1개 제외 · 외부 미반영 · 신뢰도 낮음 N건" 표시줄, 항목마다 근거 이력.
3. [정기점검] / [전문가 연결] 지정 → 해당 건물 관리자(building@)에게 조치 알림.
4. ✔ `enterprise.ss@dev.local` → G0 "기업 라이선스가 만료되었습니다".

# 2단계 — 개별 유스케이스 문서 생성 프롬프트

1단계 개요 문서의 **유스케이스 목록 순서대로**, 한 번에 하나씩 상세 문서를 생성한다.

**한 응답에 여러 UC를 몰아 쓰지 않는다.** 뒤쪽 UC의 밀도가 반드시 떨어진다.

---

## 입력

| 항목 | 값 |
|---|---|
| 대상 UC | `UC{n} {유스케이스명}` |
| 개요 문서 | `{출력폴더}/UC_00_개요_{대상명}.md` |
| 원천 | `{원천}` (1단계와 동일) |
| 출력 경로 | `{출력폴더}/UC_{nn}_{유스케이스명}.md` |

---

## 프롬프트

### [역할]

너는 UML 2.5.1 표준으로 유스케이스를 명세하는 **선임 시스템 분석가**다.
전문영역은 (1) 기본·대체·예외 흐름 설계 (2) 사전·사후조건 정의
(3) Sequence Diagram 작성 (4) 업무규칙 형식화다.

### [맥락]

독자는 이 명세로 구현에 착수할 **개발자**와 이를 승인할 **현업 담당자**다.
이 문서에 없는 흐름은 구현되지 않고, 이 문서에 없는 예외는 처리되지 않는다.

### [핵심 지시]

`UC{n} {유스케이스명}` 한 건의 상세 명세를 작성하라.
개요 문서의 해당 행(원천 근거·액터·우선순위)을 출발점으로 삼되, **원천을 다시 읽어** 세부를 채운다.

### [근거 규율] — 최우선

1. 원천에 없는 액터·외부시스템·수치·API명·규제명을 만들지 않는다. 없으면 `자료 없음 — 확인 필요`.
2. 설계 판단은 `[추론]` 표기.
3. `비고` 속성에 **원천 추적성**(캔버스 블록 키·문서 절)을 반드시 남긴다.

### [작성 절차]

1. **사전·사후조건** — 이 UC 시작 전 참이어야 할 상태 / 정상 종료 후 보장되는 상태.
   "로그인되어 있다" 같은 공통 조건도 생략하지 않는다.
2. **기본흐름** — `단계 | 액터 행위 | 시스템 행위` 3열.
   - **양쪽 열을 모두 채운다.** 시스템 독백(액터 행위가 전부 `—`)이면 UC 선정이 잘못된 것이다.
   - 3~10단계. 10단계 초과면 UC 분할을 개요 문서에 제안한다.
3. **대체흐름** — 정상이지만 다른 경로. `A1. …` 형식.
4. **예외흐름** — `E1. …` 형식. **원천의 리스크·제약·실패모드 블록에서 도출한다.**
   - **UC당 최소 1개.** 예외가 없다고 판단되면 그 판단 근거를 비고에 적는다.
5. **업무규칙** — `BR-<도메인약어>-<2자리>` 로 부여하고 §6 표에 근거와 함께 정리.
6. **Sequence Diagram** — 기본흐름을 lifeline으로 옮긴다.
   - 외부시스템·AI는 **별도 lifeline**으로 분리
   - 예외·조건 분기는 `alt` / `opt` 결합 프래그먼트로 표현
   - 기본흐름 단계와 시퀀스 메시지가 **1:1 대응**해야 한다

### [다이어그램 — PlantUML 형식과 렌더 링크]

두 다이어그램(UseCase · Sequence)은 **반드시 PlantUML 소스**로 쓰고, 소스 바로 아래에 **렌더 링크**를 단다.
렌더 서버는 사내 Kroki `https://plantuml.sumzip.com` 이다(2026-09-23 실측: 로그인 없이 열린다 · svg·png 모두 200).

**1. 소스** — ```` ```plantuml ```` 코드블록. `@startuml <식별자>` ~ `@enduml`. 첫 세 줄은 고정한다.

```
@startuml uc_<대상>_<번호>
skinparam backgroundColor #F3F1EB
skinparam shadowing false
left to right direction      ← UseCase Diagram 에만. Sequence 에는 쓰지 않는다
title <대상 시스템> — <다이어그램명>
```

- UseCase: `rectangle "<시스템>" { usecase … }` 로 경계를 그리고, 외부기관·AI는 경계 **밖** actor.
  관계는 `..>` + `<<include>>` / `<<extend>>`, 상속은 `<|--`.
- Sequence: 외부시스템·AI는 **별도 participant**. 분기는 `alt` / `opt` 로 쓰고 **예외흐름 ID(E1 등)를 메시지에 병기**한다.
- 한글은 그대로 쓴다(UTF-8). 이모지는 쓰지 않는다.

**2. 렌더 URL 만들기** — Kroki 는 **zlib deflate + base64url** 을 받는다.

```python
import base64, zlib
enc = base64.urlsafe_b64encode(zlib.compress(소스.encode("utf-8"), 9)).decode("ascii")
url = "https://plantuml.sumzip.com/plantuml/svg/" + enc
```

경로는 반드시 `/plantuml/svg/` 다(루트 `/svg/` 는 404). PNG 가 필요하면 `svg` 를 `png` 로 바꾼다.

**3. 검증 — 문서에 넣기 전에 실행한다.**

```bash
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' --max-time 20 "<렌더URL>"
# 200 image/svg+xml 이어야 한다. 200 이라도 SVG 안에 "Syntax Error" 가 있으면 실패다.
```

**4. URL 길이 한계 4096자** (실측: 4053자 통과 · 4121자에서 `414`). 넘으면 **다이어그램을 쪼갠다** —
UseCase 는 패키지별로, Sequence 는 흐름 구간별로 나눈다. 검증만 급하면 POST 로 확인할 수 있다
(`curl -X POST --data-binary @src.puml https://plantuml.sumzip.com/plantuml/svg`). 다만 **문서에 싣는 링크는 GET 형식** 이어야 한다.

**5. 코드블록과 링크는 같은 소스여야 한다.** 소스를 한 글자라도 고치면 **인코딩을 다시 해서 링크를 교체**한다.
링크는 렌더되는데 화면이 옛 그림인 실패는 눈에 보이지 않는다 — 저장 직전에 링크를 복호해 코드블록과 대조한다.

```python
zlib.decompress(base64.urlsafe_b64decode(enc + "==")).decode("utf-8") == 코드블록_원문
```

**6. 문서 삽입 형식** — 긴 URL 을 본문에 노출하지 않는다.

````markdown
```plantuml
@startuml …
@enduml
```

**[「<간결한 제목>」 PlantUML 뷰어로 열기](<렌더URL>)** — 클릭 시 브라우저로 연결됩니다.
````

렌더 서버에 닿지 않는 환경이면 소스는 그대로 두고 `주의: 렌더 검증 미수행` 을 적는다. **검증했다고 쓰지 않는다.**

### [형식]

`references/format-spec.md` **B절**을 그대로 따른다. 특히:

- `### 5.<n> UC<n> <유스케이스명>` — 번호 뒤 **명칭 필수**
- `> **쉽게 말하면** — …` — 기술 표 **직전**, 2~3문장
- 유스케이스 기술 **14속성 전부** (누락 금지)
- 다이어그램마다 렌더 링크를 `[제목](url)` 형태로 (위 «다이어그램» 절의 인코딩·검증 규칙을 그대로 따른다)

### [검증 — 저장 직전 자가점검]

- [ ] 14속성이 **전부** 있는가
- [ ] `쉽게 말하면` blockquote가 기술 표 **앞**에 있는가
- [ ] 기본흐름의 **액터 행위 열**이 채워져 있는가
- [ ] 예외흐름이 **최소 1개** 있고 원천 근거가 있는가
- [ ] 기본흐름 단계 수 == 시퀀스 주요 메시지 수 (1:1)
- [ ] `비고` 에 원천 추적성이 있는가
- [ ] 다이어그램 2개(UseCase + Sequence)가 **```plantuml 코드블록**으로 있는가
- [ ] 두 렌더 링크가 `https://plantuml.sumzip.com/plantuml/svg/…` 이고 **curl 200 · image/svg+xml** 인가
- [ ] SVG 안에 `Syntax Error` 가 없는가
- [ ] 링크를 복호한 소스가 **코드블록과 글자까지 같은가**(고친 뒤 재인코딩했는가)
- [ ] 렌더 URL 이 **4096자 이하**인가 (넘으면 다이어그램을 쪼갠다)
- [ ] 이모지·긴 URL 노출이 없는가

---

## 반복 규칙

- 1건 생성 → 저장 → **자가점검 통과 확인** → 다음 UC
- 개요 문서의 `상태` 열은 3단계에서 일괄 갱신한다(여기서 매번 고치지 않는다)
- 생성 중 원천에 없는 정보가 필요해지면 **지어내지 말고** `자료 없음 — 확인 필요` 로 남기고,
  3단계 결론의 "미해결 사항"에 모은다

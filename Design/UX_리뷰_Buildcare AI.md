## 1. 결론 요약

- **UX 구조(SD_02)는 강하다. 시각 언어(v1 스타일가이드)는 주제와 맞지 않았다.** SD_02 의 원칙 U1~U8 과 게이트→화면 사상은 그대로 두고, 그 위에 입힌 시각·상호작용 층을 현장 점검·유지관리 도구에 맞게 다시 만들었다.
- v1 은 `npx getdesign add bmw` 의 **자동차 브랜드 마케팅 사이트** 분석을 옮긴 것이다. 대형 히어로, 다크 밴드, Light 300 본문, 영문 대문자 라벨은 "차를 사고 싶게 만드는" 문법이고, 우리 사용자는 "외벽 균열을 정확히 기록하고 AI 를 과신하지 않아야 하는" 사람들이다.
- v2 는 **현장 점검 앱 · 결함 관리(펀치리스트) · 시설 유지보수(CMMS) · AI 보조진단 · 리스크 대시보드** 다섯 분야의 검증된 패턴을 가져와 P0~P8 에 맞췄다. 원칙 6개, 위험도 3단계, 출처 표지 3종, 도메인 컴포넌트 C1~C8 을 정의하고 8개 화면에 적용했다.

## 2. 검토 — 무엇이 문제였나

### 2-1 잘 된 것 (유지)

| 항목 | 위치 | 판단 |
|---|---|---|
| 게이트를 화면에 사상(막힌 이유 · 푸는 사람 · 다음 행동) | SD_02 §12 · U1 | 이 서비스 UX 의 뼈대. 그대로 유지 |
| 1차 참고용 고지를 결과 안에 고정 | SD_02 U2 · C4 | `[부정적 영향]` 대응의 핵심. 유지 |
| 판정 불가를 일치·불일치와 분리 | SD_02 U4 · SD_03 D6 | 신뢰도 지표 오염 방지. 유지하고 시각적으로 더 분리 |
| 연동 실패 시 계속 보이기 + 빠진 것 표시 | SD_02 U5 · C7 | 유지 |
| 역할별 뷰(S7A/S7B · S8A/S8B) | SD_02 §2-1 | 유지 — 역할별 밀도(P5) 원칙으로 확장 |

### 2-2 문제 (수정)

| # | 문제 | 심각도 | 근거 | v2 조치 |
|:--:|---|:--:|---|---|
| 1 | 마케팅 문법(64px 히어로 · 다크 밴드 · CTA 밴드)을 업무 도구에 적용 | 높음 | 사용자는 반복 작업자. 첫 화면에 정보가 없다 | 대형 히어로 폐지. 타입 스케일 최대 30px. 앱 셸(사이드 내비 + 진행 레일) |
| 2 | 본문 Light 300 | 높음 | 야외 모바일·한글 가는 획은 판독성 급감. 현장 입력(U7)과 충돌 | 본문 400, 굵기 400·600·700 세 단계 |
| 3 | Warning #f59e0b 를 글자색으로 사용 가능(흰 바탕 2.1:1) | 높음 | SD_02 §13-1 이 이미 경고. WCAG 1.4.3 | 위험도마다 글자색·바탕색·막대색 분리. 모든 상태 글자 4.5:1 이상 실측 |
| 4 | 상태를 색으로만 구분할 여지 | 중간 | SD_02 §13-1 "글자+색+형태" 를 토큰이 지원하지 않음 | 상태 태그에 도형 고정(원·마름모·삼각형·선) |
| 5 | AI 문장과 사람의 기록이 시각적으로 같음 | 높음 | `[부정적 영향]` AI 과신 · `[핵심 장벽] 3단계` 진단 책임 | 출처 표지 3종(AI 인디고 · 현장 · 전문가 청록)을 C6·타임라인·비교 화면 전 값에 |
| 6 | AI 신뢰도를 숫자(0.82)로만 표현 | 중간 | 비전문가에게 0.82 는 "82% 맞다"로 읽힘 | 말 + 3칸 막대(높음·보통·낮음). 낮음엔 다음 행동(다시 촬영) |
| 7 | 영문 대문자 자간 라벨(LEARN MORE) | 낮음 | 한국어 화면에서 의미 없음 | 폐지. 버튼은 동사로 끝나는 한국어 |
| 8 | 0px 직각 일괄 | 낮음 | 누를 수 있는 것과 아닌 것의 구분이 약함 | 버튼·입력 6px, 카드 10px, 태그 4px |
| 9 | M 트라이컬러 등 브랜드 무관 요소 | 낮음 | 출처가 다른 브랜드 | 폐지 |
| 10 | 도메인 컴포넌트(C1~C8)가 스타일가이드에 없음 | 높음 | SD_02 가 정의했지만 시각 사양 부재 → 화면마다 다르게 구현될 위험 | 스타일가이드 §07 에 C1~C8 + 신뢰도 미터를 사양화 |
| 11 | 현장 입력 패턴 부재(촬영 가이드 · 저장 상태 · 하단 고정 저장) | 높음 | `[혜택] 2단계` 점검시간 절감 · 기록 표준화 · UC3 E4 | 촬영 가이드 · 임시 저장 상태 · 엄지 위치 저장 바 |
| 12 | S3 건물 유형이 입력 드롭다운 | 중간 | SD_03 §19-1-1 상류 피드백 | 읽기 전용 표시로 변경 |

## 3. 도메인 레퍼런스 — 무엇을 가져왔나

| 분야 | 대표 제품군 | 가져온 패턴 | 우리 화면 | 근거 블록 |
|---|---|---|---|---|
| 현장 점검 앱 | SafetyCulture · Fieldwire 류 | 사진 중심 입력, 필수 항목 우선, 오프라인·임시 저장 상태 상시 표시, 큰 터치 영역 | S2 · S3 · S7B | `[혜택] 2단계` · UC3 E4 |
| 결함 관리(펀치리스트) | Procore · 스내깅 앱 류 | 위치 + 하자 종류 + 상태 + 담당자를 한 카드에, 위치로 묶기 | S3 · S5 | BR-DEF-06 · BR-DEF-12 |
| 시설 유지보수(CMMS) | UpKeep · Fiix 류 | 기한별 작업 큐(지연 → 이번 주 → 예정), 지연 일수 표기, 카드당 다음 행동 하나 | S7B · S7A | UC6 · P0 · `[부정적 영향]` 점검 지연 |
| AI 보조진단 | 의료영상 판독 보조 류 | AI 결과에 출처·신뢰도·한계 고지 상시, 사람 판독과 나란히 비교, 판독 불가 분리 | S2 · S4 | BR-DEF-01 · BR-DEF-07 · INC2 |
| 리스크 대시보드 | 자산·보험 리스크 관리 류 | 순위마다 이유 칩과 근거 링크, 데이터 결손·신뢰도를 표 위에, 스냅숏 시점 표기 | S6 | BR-DEF-12 · UC8 E1~E4 |
| 동의·결제 확인 | 의료정보 제공 동의 · 결제 확인 | 보낼 것/안 보낼 것 목록 + 금액을 확정 버튼 위에, 받는 사람 이름이 들어간 동의 문장 | S8A · S1 | G9 · BR-DEF-09 · BR-DEF-11 |

레퍼런스는 패턴 수준에서만 참고했다. 상류 문서(UC · SD_01~03)에 없는 기능은 추가하지 않았다. 촬영 가이드·신뢰도 문구는 기능이 아니라 기존 게이트(G3)와 업무규칙(BR-DEF-01·04)을 돕는 안내다.

## 4. 적용 — 무엇이 바뀌었나

### 4-1 디자인 원칙 (스타일가이드 §01)

| 원칙 | 한 줄 | 주로 지키는 것 |
|---|---|---|
| P1 Field-first | 현장 화면은 한 손·엄지·야외 밝기 기준 | U7 · `[혜택] 2단계` |
| P2 Explainable AI | AI 는 출처·신뢰도·고지와 함께 말한다 | U2 · BR-DEF-01 |
| P3 Say the state | 상태는 글자 + 색 + 모양 | SD_02 §13-1 |
| P4 Block becomes path | 막힘에는 이유·푸는 사람·다음 행동 | U1 |
| P5 Role density | 역할마다 밀도를 다르게 | SD_02 §2-1 |
| P6 Calm by default | 색은 위험할 때만 | 경보 피로 방지 |

### 4-2 v1 → v2 대조

| 항목 | v1 (BMW 기반) | v2 (Buildcare) |
|---|---|---|
| 성격 | 자동차 브랜드 마케팅 사이트 | 현장 점검·유지관리 업무 도구 |
| 서체 | Inter + Noto Sans KR, 700/300 | Pretendard, 400/600/700, tabular 숫자 |
| 최대 제목 | 64px | 30px |
| 본문 | 16px Light 300 | 15px(모바일 16px) Regular 400 |
| 액션색 | #1c69d4 단일 | #1c69d4 단일 (유지) |
| 중립색 | 따뜻한 회색 | 차가운 슬레이트 (도면·콘크리트 톤) |
| 상태색 | Success·Warning·Error 단색 | 위험도 3단계 × (글자·바탕·막대) + 도형, 해당 없음 |
| 출처 구분 | 없음 | AI · 현장 · 전문가 표지 |
| 모서리 | 0px 일괄 | 4 / 6 / 10 |
| 컴포넌트 | 마케팅(히어로·모델 카드·CTA 밴드) | 도메인(C1~C8 · 신뢰도 · 작업 카드 · 재발 묶음 · 비교 판독) |
| 토큰 파일 | 페이지 내부 | `assets/buildcare-ui.css` 공용 (스타일가이드 · 프로토타입이 같은 파일 사용) |

SD_02 가 참조하는 토큰 이름(`--primary-disabled` · `--muted` · `--ink` · `--surface-soft` · `--body`)은 같게 유지해 문서 간 참조가 깨지지 않는다.

### 4-3 화면별 적용 (UI 프로토타입)

| 화면 | 적용 패턴 | 확인할 상호작용 |
|---|---|---|
| S2 하자 분석 | 촬영 가이드 → 판정·원인·할 일·고지 순서 결과, 출처·신뢰도, 비회원 결과 보관(FR-120a), 일반 사용자 요청 버튼 없음(FR-121) | 상단 전환: 입력 / 품질 차단 G3 / 결과 |
| S1 이용권 | 금액·차감 규칙을 결제 버튼 위에, G2 문구 S2 와 동일 | 요금제 선택 |
| S7B 내 배정 점검 | 기한별 작업 큐, "지연 3일", 카드당 행동 하나, G6 요청을 자료 보유자 화면에 | 카드 버튼 → S3 |
| S3 현장 기록 | 필수 항목 상단 + 남은 개수, 건물 유형 읽기 전용, 미완료 명시값, 하단 고정 저장 바 + 임시 저장 상태 | 보수 결과 선택 → G5 해제 → 저장 |
| S4 전문가 검증 | AI·현장 나란히, 차이 형광, 판정 불가 분리 | [판정할 수 없음] → G6 블록 |
| S5 건물 이력 | 연동 실패 표시줄, 위치로 묶은 재발 카드, G7 블록, 출처 표지 타임라인 | 탭 전환 |
| S6 우선순위 | 지표 4개, 결손·신뢰도·스냅숏 표시줄, 순위마다 이유 칩·근거 링크 | 조치 선택 |
| S8A 전문가 요청 | 보낼 것/안 보낼 것 + 수수료가 확정 위, 받는 사람 이름이 든 동의, G9 → G10 대기 | 동의 체크 → 확정 → G10 |

검증: Chromium 헤드리스로 1440px · 390px 두 폭에서 8개 화면을 렌더해 확인했다. 상태 글자 대비는 스크립트로 실측했다(최저 5.2:1).

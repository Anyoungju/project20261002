# SD_03 데이터베이스 설계서 생성 프롬프트

유스케이스·프로세스·화면 설계가 끝났다. 이제 **그 화면들이 표출하는 모든 값이 어디에 어떻게 저장되는지**를 정한다.
이 문서의 판정 기준은 하나다 — **SD_02 의 어떤 항목을 가리켜도 "이 테이블 이 컬럼" 또는 "이 식으로 유도"라고 답할 수 있는가.**

## 입력

| 항목 | 값 |
|---|---|
| UI/UX 설계서 | `{출력폴더}/SD_02_UIUX설계서_{대상명}.md` — 화면별 **영역별 설계(데이터 바인딩)** · 컴포넌트 |
| 프로세스 설계서 | `{출력폴더}/SD_01_프로세스설계서_{대상명}.md` — IPO Output · **게이트 맵** · 인계 계약 |
| 유스케이스 | `{출력폴더}/UC_*.md` 전건 — **사후조건** · 업무규칙 BR |
| 원천 | `{원천}` — 보존·보안·규제 제약 |
| 출력 경로 | `{출력폴더}/SD_03_데이터베이스설계서_{대상명}.md` (+ DDL 파일 `{대상약칭}_ddl.sql`) |

---

## 프롬프트

### [역할]

너는 업무 시스템의 논리·물리 데이터 모델을 설계하는 **선임 데이터 아키텍트**다.
전문영역은 (1) 화면·프로세스에서 데이터 요구 도출 (2) 정규화와 **유도속성 판정**
(3) 업무규칙의 제약 구조화 (4) 이력·역추적 설계 (5) 표준 SQL DDL 작성이다.

### [맥락]

독자는 이 설계로 스키마를 올릴 **개발자**와, 여기 걸린 제약을 근거로 예외를 처리할 **애플리케이션 설계자**다.
**산문으로 적힌 업무규칙을 제약으로 옮기는 것이 이 문서의 핵심 작업**이다.
옮겨지지 않는 규칙이 있다면 그 규칙이 모호한 것이므로, 상류 문서로 돌려보내 다듬는다.

### [근거 규율] — 최우선

1. **화면에 없는 컬럼을 만들지 않는다.** 모든 컬럼은 SD_02 의 표시 항목, SD_01 의 IPO Output,
   또는 UC 의 사후조건 중 하나로 역추적되어야 한다. 셋 다 아니면 그 컬럼은 **상상**이다.
2. **UC 의 모든 사후조건이 «어느 테이블의 어느 컬럼 변화»인지** 답해져야 한다.
3. **SD_01 의 모든 게이트가 데이터로 표현**되어야 한다.
4. 보존기간·임계값·규제명이 원천에 없으면 **지어내지 않고** 미해결 절에 남긴다.
   컬럼은 두되 상수는 비워 두는 방식이 정직하다.

### [작성 절차]

1. **표출 항목 전수 수집** — SD_02 의 모든 화면·컴포넌트를 훑어 화면에 뜨는 항목을 **하나도 빠뜨리지 않고** 모은다.
   표 열: `화면 | 영역 | 표시 항목 | 성격(저장·유도·상수) | 근거(IPO·UC)`.
   이 목록이 이후 모든 판단의 출발점이다.
2. **저장 속성과 유도 속성 분리** — 위 목록의 각 항목을 판정한다.

   | 판정 | 기준 | 처리 |
   |---|---|---|
   | **저장** | 외부에서 들어오거나 사람이 결정한 값 | 컬럼으로 만든다 |
   | **유도** | 다른 저장 값으로 **계산 가능**한 값 | 원칙적으로 **저장하지 않는다** |
   | **유도인데 저장** | 계산 시점의 값을 **고정해야** 하는 경우(판본·증빙·감사) | 저장하되 **고정 근거와 재계산 금지 사유**를 적는다 |

   유도 속성은 **별도 표로 총괄**한다 — 열: `유도 속성 | 산출식 | 입력 컬럼 | 산출 시점 | 구현 위치 | 저장 여부와 근거`.
   구현 위치는 `뷰` · `생성 컬럼(GENERATED)` · `애플리케이션` 중 하나로 **명시**한다.
   **같은 유도값을 두 곳에서 계산하지 않는다.** 두 곳에서 계산하면 언젠가 두 값이 달라지고, 그때 어느 쪽이 맞는지 아무도 모른다.
3. **영역 구분과 개념 모델** — 엔티티를 업무 영역 `A`~`G` 로 나눈다(수집·설계·산정·이력·문서승인·보고·공통추적 등 도메인에 맞게).
   영역 경계는 **쓰기 주체와 생애주기**로 가른다. 개념 모델 도면을 먼저 두어 큰 그림을 보인다.
4. **ERD 작성** — §전체 ERD 1장 + **영역별 ERD** 각 1장. 전체 도면은 컬럼을 PK·FK·식별 컬럼으로 줄이고,
   영역 도면에서 상세를 보인다. 한 도면에 전부 담지 않는다.
5. **엔티티 명세** — 영역마다 표: `엔티티 | 용도 | 핵심 컬럼 | 쓰기 주체 | 생애주기`.
   설계 판단이 갈린 컬럼(상태 머신·다형 참조·판본 고정 등)은 **별도 소절로 이유를 쓴다.**
6. **게이트의 데이터 표현** — SD_01 게이트 전건을 표로 사상한다: `게이트 | 판정 근거 데이터 | 차단 구현 | 해제 기록`.
   게이트 이벤트를 **1급 엔티티**로 승격해 발생·해제를 이력으로 남긴다. 판정은 **단일 지점**(뷰 또는 함수)에서만 한다.
7. **근거(evidence) 역추적 경로 설계** — "화면의 이 숫자가 어디서 왔는가"를 최소 2~3경로로 설계하고,
   경로마다 **실제 조인 SQL**을 싣는다. 역추적 경로 도식 1장을 둔다.
8. **사상표** — `IPO 단계 → 테이블` 과 `UI 컴포넌트 → 테이블` 두 표로 상류와의 연결을 닫는다.
9. **무결성 제약** — UNIQUE · CHECK · FK · 인덱스. **업무규칙 BR 마다 대응 제약을 명시**한다.
   CHECK 로 표현할 수 없는 규칙(시점 의존·다중 행 조건)은 **트리거 또는 애플리케이션 책임**으로 명시하고 그 이유를 적는다.
   숨기지 않는다 — 어디서 강제되는지 모르는 규칙이 가장 위험하다.
10. **보존·마스킹·감사** — 민감 정보 저장 형태와 조회 경로(마스킹 뷰), 외부 반출 감사, 보존 방침.
11. **DDL 완성** — 아래 [SQL] 절의 규약대로 실행 가능한 전문을 만든다.

### [문서 구조] — 이 순서를 지킨다

```
§1 설계 원칙                    (+ 1-1 명명·타입 규약)
§2 표출 항목과 유도 속성          2-1 화면 표출 항목 전수 · 2-2 저장/유도 판정 · 2-3 유도 속성 총괄표
§3 영역 구분과 개념 모델
§4 전체 ERD
§5 ~ §N 영역별 (A, B, … 각각 한 절)   N-1 ERD · N-2 엔티티 명세 · N-3 핵심 컬럼 설계 판단
§N+1 근거 역추적 구현             (경로별 조인 SQL + 경로 도식)
§N+2 게이트의 데이터 표현
§N+3 IPO·UI 대 테이블 사상
§N+4 무결성 제약과 인덱스          (UNIQUE · CHECK · 다형 참조 점검 · 인덱스)
§N+5 보존·마스킹·감사
§N+6 DDL 전문 (또는 별도 .sql 파일 참조)
§N+7 미해결·확인 필요
```

ERD 는 **8장 내외**(전체 1 + 영역별 6~7 + 역추적 도식 1)가 기준이다.

### [다이어그램 — ERD (PlantUML entity)]

```
@startuml
hide circle
skinparam backgroundColor #F3F1EB
skinparam shadowing false
skinparam linetype ortho
title 전체 ERD - <대상 시스템>

entity "sales_order" as so {
  * so_id <<PK>>
  --
  code
  status
  customer_id <<FK>>
}
entity "cost_line" as cl {
  * line_id <<PK>>
  --
  cost_id <<FK>>
  price_kind
  amount <<derived>>
}

so ||--o{ cl
@enduml
```

**문법 함정 — 실측 확인됨**

- `entity "x" as x {` 뒤의 **속성은 반드시 다음 줄부터** 쓴다. 여는 중괄호와 같은 줄에 첫 속성을 붙이면
  Kroki 가 **HTTP 400** 을 돌려준다(오류 이미지가 아니라 요청 자체가 실패한다).
- `*` = 필수, `--` = PK 구분선, 스테레오타입 `<<PK>>` `<<FK>>` `<<derived>>` 모두 렌더된다.
- 관계 표기(전부 검증됨): `||--o{`(1:N) · `||--|{`(1:N 필수) · `}o--||`(N:1) · `|o--o{`(0:N) ·
  점선 `}o..o|`(약한·다형 참조, 라벨 권장) .
- `skinparam linetype ortho` 로 선을 직각으로 정리한다. 엔티티가 20개를 넘으면 **영역별로 쪼갠다.**
- **유도 속성은 ERD 에 `<<derived>>` 로 표시**하되, 저장하지 않는 것은 엔티티 안에 넣지 말고 §2-3 표와 뷰 정의로만 둔다.

### [SQL — 표준 SQL DDL]

- **표준 SQL 로 쓴다.** 특정 DBMS 전용 구문이 불가피하면 그 사실과 이유를 **주석으로 남긴다.**
- 생성 순서를 **FK 의존 위상으로 정렬**한다. 참조되는 테이블이 먼저다.
- **멱등**하게 만든다 — 재실행해도 실패하지 않아야 한다.
- 업무규칙 제약에는 **어느 BR 의 구현인지 주석**을 단다:

```sql
-- BR-PRC-02: 미등록 항목은 금액을 생성하지 않는다
ALTER TABLE cost_line ADD CONSTRAINT chk_unregistered_no_amount
  CHECK (price_kind <> 'unregistered' OR amount IS NULL);
```

- 다형 참조(FK 를 걸 수 없는 관계)는 **주기 점검 쿼리**를 함께 싣는다.
- 단일 판정 지점이 필요한 곳(게이트 판정·검증 통과 행 노출)은 **뷰**로 고정한다.
- **실행 검증 3종을 통과해야 완료다**: ① 무오류 실행 ② 재실행 가능(멱등) ③ **위반을 시도해 실제로 거부되는지 확인**.
  ③을 하지 않은 제약은 주석과 다를 바 없다.
- 실행 중 논리 설계와 어긋나 수정했다면 **이탈 사유를 파일 주석으로 남긴다**
  (실측 사례: 사용자 변수를 쓴 마스킹 뷰가 MariaDB 에서 생성 불가 → 복호화 없는 형태로 재작성).

### [렌더 — plantuml.sumzip.com]

```python
import base64, zlib
enc = base64.urlsafe_b64encode(zlib.compress(소스.encode("utf-8"), 9)).decode("ascii")
url = "https://plantuml.sumzip.com/plantuml/svg/" + enc      # 경로는 반드시 /plantuml/svg/
```

```bash
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' --max-time 20 "<렌더URL>"   # 200 image/svg+xml
```

- **HTTP 400 = 문법 오류**(위 «문법 함정» 을 먼저 본다). 200 이어도 SVG 안에 `Syntax Error` 가 있으면 실패다.
- URL 4096자 이하. 전체 ERD 가 넘으면 **컬럼을 PK·FK 로 줄이거나 영역별로 분할**한다.
- 소스를 고치면 재인코딩하고, 복호해서 코드블록과 대조한다.
- 삽입 형식: `**[「<도면명>」 PlantUML 뷰어로 열기](<url>)** — 클릭 시 브라우저로 연결됩니다.`

### [검증 — 저장 직전 자가점검]

- [ ] SD_02 의 **모든 표출 항목**이 §2 전수표에 있는가 (누락 0건)
- [ ] 각 표출 항목이 **저장·유도·상수** 중 하나로 판정되었는가
- [ ] 유도 속성마다 **산출식 · 입력 컬럼 · 산출 시점 · 구현 위치**가 적혔는가
- [ ] **같은 유도값을 두 곳에서 계산하지 않는가**
- [ ] 저장하기로 한 유도 속성에 **고정 근거**가 적혔는가
- [ ] UC 의 **모든 사후조건**이 어느 테이블 어느 컬럼 변화인지 답해지는가
- [ ] SD_01 의 **모든 게이트**가 데이터로 표현되었는가 · 판정이 **단일 지점**인가
- [ ] 모든 BR 에 대응 제약(CHECK·UNIQUE·트리거·앱)이 **명시**되었는가 — 미구현 규칙이 숨어 있지 않은가
- [ ] 역추적 경로마다 **실제 조인 SQL**이 있는가
- [ ] DDL 이 **FK 위상 정렬 · 멱등 · 위반 거부 확인** 3종을 통과했는가
- [ ] DBMS 전용 구문에 **이유 주석**이 달렸는가
- [ ] 모든 ERD 링크가 **curl 200 · image/svg+xml** 이고 `Syntax Error` 가 없는가
- [ ] 링크를 복호한 소스가 **코드블록과 글자까지 같은가** · URL 4096자 이하인가
- [ ] 보존기간·임계값을 지어내지 않고 미해결에 남겼는가
- [ ] 이모지·긴 URL 노출이 없는가

### [금지]

- 화면·IPO·사후조건 어디에도 없는 컬럼 생성
- 유도 가능한 값을 근거 없이 저장 (또는 저장해 놓고 갱신 규칙을 정하지 않기)
- 제약을 선언만 하고 위반 시도로 검증하지 않기
- 임계값·보존기간을 임의로 정하기
- 이모지 · 긴 URL 원문 노출
